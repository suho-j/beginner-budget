# 가계부 탭·수정·캘린더·미리보기 배포 설계

- 작성일: 2026-08-11
- 상태: 대화 설계 승인, 문서 검토 대기
- 대상 저장소: `suho-j/beginner-budget`
- 개발 브랜치: `guardian/project-setup`

## 1. 목적

현재 정적 가계부의 기술 구성을 유지하면서 입문자가 월별 예산과 사용 내역을 더 쉽게 탐색하고 정정할 수 있도록 다음 기능을 추가한다.

1. 카테고리 하나씩 선택하는 사용 내역 필터
2. 거래의 날짜, 유형, 카테고리, 금액, 메모 수정
3. 이전·현재·다음 달의 예산과 사용 내역 조회
4. 날짜별 합계와 상세 내역을 제공하는 월간 캘린더
5. 긴 단일 화면을 `홈 · 내역 · 캘린더 · 설정` 탭으로 재구성
6. 운영 사이트를 유지한 채 별도 미리보기 URL에서 검수한 후 동일 커밋을 운영에 승격

최상위 성공 기준은 “입문자가 설명 없이 오늘 바로 기록하고, 지난 기록을 찾아 안전하게 고칠 수 있는가”이다.

## 2. 현재 기준 상태

2026-08-11 확인 결과는 다음과 같다.

- 운영 GitHub Pages는 `master` 루트에서 배포된다.
- 운영 URL은 `https://suho-j.github.io/beginner-budget/`이며 HTTP 200을 반환한다.
- 운영 소스 커밋은 `0d487df`이다.
- 개발 브랜치 `guardian/project-setup`은 `origin/master`와 같은 커밋이다.
- 기능 관련 추적 파일 변경은 없다.
- `.superpowers/`만 로컬의 추적되지 않은 시안 도구 자료로 남아 있으며 기능 커밋에 포함하지 않는다.
- GitHub 기본 브랜치 `main`은 앱 운영 이력과 별개이므로 수정하거나 배포 기준으로 사용하지 않는다.
- 앱은 빌드 없는 HTML/CSS/Vanilla JS이며 Supabase Auth와 RLS를 사용한다.
- 실제 가계부 데이터는 브라우저 `localStorage`가 아니라 Supabase의 `budget_settings`, `transactions`에 저장된다.

## 3. 범위와 비범위

### 포함

- 기존 정적 앱 안에서 탭, 공통 월 탐색, 거래 필터·수정, 캘린더를 추가한다.
- 과거 월도 현재 월과 동일하게 조회·수정·삭제할 수 있다.
- 일반 저장을 거래 행 단위 Supabase 변경으로 전환한다.
- 모바일 360px, 키보드, 스크린리더 사용 흐름을 지원한다.
- 별도 GitHub Pages 미리보기 사이트를 만든다.
- 미리보기와 운영은 같은 Supabase 운영 데이터를 사용한다.
- 자동 테스트, 미리보기 브라우저 검수, 사용자 승인 후 운영 배포까지 수행한다.

### 제외

- React/Vite 등 프레임워크 전환
- 회원가입 또는 다중 사용자 계정 UX 추가
- Supabase 테이블·RLS 정책 변경
- 카테고리 추가·삭제 기능
- 여러 카테고리를 동시에 선택하는 고급 필터
- 운영 승인 전 `origin/master` 변경

## 4. 화면 구조

### 4.1 공통 월 탐색

앱 상단에 선택 월과 `이전 달 · 이번 달 · 다음 달` 이동 수단을 둔다. 선택 월은 네 탭이 공유하는 화면 상태이며 브라우저 저장소에 영구 보관하지 않는다.

예산 시작일이 1일이 아니면 선택 월 아래에 실제 예산 기간을 표시한다. 예를 들어 시작일이 25일이면 `2026년 8월 예산 · 8/25~9/24`처럼 안내한다.

### 4.2 홈

- 선택 월의 월 예산, 총지출, 잔액, 카테고리 현황을 보여준다.
- 기존 거래 입력 폼을 유지한다.
- 입력 성공 후 요약, 내역, 캘린더가 같은 메모리 상태를 기준으로 갱신된다.

### 4.3 내역

- 월, 수입/지출 유형, 검색어, 카테고리 하나를 조합해 필터링한다.
- 카테고리 기본값은 `전체`이다.
- 유형이 바뀌면 선택 가능한 카테고리도 수입/지출에 맞춰 바뀐다.
- 각 행은 `수정`과 `삭제` 동작을 제공한다.
- 결과 건수와 필터 결과 없음 상태를 명확히 표시한다.

### 4.4 수정 모달

- 기존 거래의 날짜, 유형, 카테고리, 금액, 메모를 모두 채운 상태로 연다.
- 유형 변경 시 카테고리 선택지를 다시 구성한다.
- 추가 입력과 동일한 정규화·검증 규칙을 적용한다.
- 저장 성공 전에는 모달을 닫거나 화면 상태를 확정하지 않는다.
- 저장 성공 후 모달을 닫고 원래 수정 버튼 또는 해당 내역으로 포커스를 돌린다.
- 날짜를 다른 월로 변경해 현재 필터에서 사라지면 저장 성공 메시지로 이유를 안내한다.

### 4.5 캘린더

- 선택 예산 기간에 포함되는 날짜를 주 단위 격자로 표시한다.
- 날짜 칸에는 지출 합계와 거래 건수를 표시한다.
- 수입이 있는 날은 초록색 금액 또는 별도 수입 표시로 구분한다.
- 날짜를 누르면 아래 상세 영역에 해당 날짜 거래를 표시한다.
- 상세 거래에서도 같은 수정 모달과 삭제 흐름을 사용한다.
- 예산 기간 밖의 날짜는 흐리게 표시하고 상세 선택 대상에서 제외한다.

### 4.6 설정

- 월 예산
- 카테고리별 예산
- 예산 시작일
- 로그인·로그아웃
- JSON 백업·가져오기·초기화

기존 설정 기능을 한곳에 모으되 동작과 데이터 형식은 유지한다.

## 5. 모듈 책임

### `js/storage.js`

- 기존 상태 정규화, 날짜·월 계산, 입력 데이터 검증 기반을 유지한다.
- 가계부 데이터를 `localStorage`에 저장하지 않는다.
- 캘린더 기간 계산에 필요한 순수 날짜 헬퍼만 필요한 범위에서 추가한다.

### `js/transactions.js`

- `updateTransaction` 순수 상태 변경 함수
- 카테고리 조건을 포함한 `filterTransactions`
- 날짜별 지출·수입·건수 집계
- 특정 날짜의 정렬된 거래 조회

모든 새 도메인 로직은 DOM이나 Supabase에 의존하지 않아 단위 테스트할 수 있어야 한다.

### `js/cloud.js`

- 설정 저장은 기존 `budget_settings` upsert를 유지한다.
- 거래 추가는 한 행 insert, 수정은 거래 ID와 사용자 ID 조건 update, 삭제는 같은 조건 delete로 처리한다.
- 일반 거래 변경에서 사용자 거래 전체 삭제 후 재등록하는 동작을 제거한다.
- 전체 교체는 사용자가 명시적으로 확인한 JSON 가져오기·초기화에서만 허용한다.
- 모든 요청은 현재 인증 사용자와 RLS를 전제로 한다.

### `js/ui.js`

- 탭 상태와 패널 표시
- 월 탐색 제어 상태
- 카테고리 필터 옵션
- 내역 목록의 수정·삭제 버튼
- 수정 모달의 열기·닫기·포커스 복원
- 캘린더와 선택 날짜 상세 렌더링
- 짧은 한국어 상태 메시지와 live region 알림

동적 사용자 데이터는 원칙적으로 `textContent`로 출력한다.

### `js/app.js`

- 공통 화면 상태: 선택 탭, 선택 월, 유형, 검색어, 카테고리, 선택 날짜
- UI 이벤트와 순수 도메인 함수 연결
- Supabase 성공 후 메모리 상태 확정 및 렌더링
- 실패 시 기존 상태와 사용자 입력 유지

`app.js`에 계산 로직을 중복하지 않고 각 모듈의 공개 함수만 조정한다.

## 6. 데이터 저장 흐름

### 일반 거래 추가·수정·삭제

1. 입력을 정규화하고 검증한다.
2. 저장 버튼을 잠그고 진행 상태를 알린다.
3. 현재 사용자 권한으로 해당 거래 행만 Supabase에서 변경한다.
4. 성공하면 메모리 상태를 변경하고 관련 화면을 다시 그린다.
5. 실패하면 메모리 상태를 바꾸지 않고 입력을 유지한 채 오류를 알린다.

이 흐름은 다른 브라우저에서 추가된 거래 전체를 오래된 화면 상태로 덮어쓰는 위험을 줄인다. 같은 거래를 여러 브라우저에서 동시에 수정하는 경우에는 마지막으로 성공한 행 단위 저장이 반영된다.

### 예산 설정

선택 월 예산과 카테고리별 예산은 기존 `budget_settings` 구조의 `__monthly_budgets`를 유지해 저장한다. DB 스키마 변경은 없다.

### 가져오기·초기화

전체 교체 의도를 확인하는 기존 확인창을 유지한다. 가져오기 데이터는 먼저 전부 정규화·검증하며, 파괴적 동작 전에 JSON 백업을 쉽게 받을 수 있게 안내한다. 일반 거래 저장 경로와 전체 교체 경로를 분리한다.

## 7. 미리보기 배포

### 7.1 배포 경계

- 운영 저장소: `suho-j/beginner-budget`
- 운영 Pages: `https://suho-j.github.io/beginner-budget/`
- 미리보기 저장소: `suho-j/beginner-budget-preview`
- 예상 미리보기 Pages: `https://suho-j.github.io/beginner-budget-preview/`

2026-08-11 기준 미리보기 저장소 이름은 사용 가능하다. 구현과 검증이 끝난 뒤 생성하며, 그 전에는 외부 저장소를 만들지 않는다.

별도 저장소를 쓰는 이유는 현재 저장소의 GitHub Pages가 `master` 루트 한 곳만 배포하는 legacy 설정이기 때문이다. 미리보기 저장소의 `main` 루트에서 정적 앱을 배포하면 운영 `master`와 운영 URL을 전혀 바꾸지 않고 별도 공개 URL을 제공할 수 있다.

### 7.2 운영 데이터 사용

미리보기는 운영과 같은 Supabase URL, 공개 키, 로그인 계정, `budget_settings`, `transactions`를 사용한다. 따라서 미리보기에서 추가·수정·삭제한 내용은 운영 화면에도 반영된다.

오조작을 막기 위해 미리보기 호스트에서만 다음 고정 안내를 표시한다.

> 개발 화면 · 운영 데이터 사용 중

자동 브라우저 검증은 고유한 QA 메모를 가진 거래만 생성·수정·삭제하고 종료 전에 제거한다. 예산 저장 검증이 필요하면 기존 값을 먼저 읽어 보관한 뒤 정확히 복원한다. 자동 검증에서 가져오기·전체 초기화는 실행하지 않는다.

### 7.3 미리보기 게시

1. 개발 브랜치에서 자동 테스트와 로컬 브라우저 검증을 통과한다.
2. 코드 diff와 문서 변경을 검토한다.
3. 빈 미리보기 저장소를 만들고 별도 Git remote를 추가한다.
4. `guardian/project-setup`의 검증된 커밋을 미리보기 저장소 `main`으로 push한다.
5. 미리보기 저장소 Pages를 `main` 루트로 활성화한다.
6. 공개 미리보기 URL의 HTTP, 콘솔, 데스크톱·360px 핵심 흐름을 검증한다.
7. 사용자에게 미리보기 URL과 알려진 제한을 전달하고 검수 승인을 기다린다.

미리보기 push는 원본 저장소의 upstream을 바꾸지 않으며 `origin/master`를 건드리지 않는다.

### 7.4 운영 승격

사용자 승인 뒤 미리보기에서 검증한 정확한 커밋을 `origin/master`로 fast-forward push한다. 별도로 다시 구현하거나 파일을 복사하지 않는다.

운영 Pages가 `built` 상태가 된 후 다음을 다시 확인한다.

- 운영 URL HTTP 200
- 로그인과 데이터 다운로드
- 월 이동과 탭
- 카테고리 필터
- 거래 추가·수정·삭제
- 캘린더 상세
- 콘솔 오류 없음
- 모바일 360px 레이아웃

문제가 생기면 새 수정 커밋 또는 `git revert`로 복구하며 강제 push는 사용하지 않는다.

## 8. 오류 처리와 접근성

- 네트워크 저장 중 중복 제출을 막는다.
- 저장 실패 시 입력과 기존 데이터를 유지한다.
- 삭제 전 날짜·카테고리·금액을 포함한 확인 메시지를 표시한다.
- 탭은 `tablist`, `tab`, `tabpanel` 의미와 선택 상태를 제공한다.
- 키보드로 탭을 이동하고 활성화할 수 있어야 한다.
- 모달은 Escape로 닫을 수 있고, 내부 포커스를 관리하며, 닫힌 뒤 호출 지점으로 복원한다.
- 캘린더 날짜 버튼은 날짜, 지출 합계, 건수, 수입 여부를 스크린리더 이름으로 제공한다.
- 저장·오류·필터 결과 변화는 live region으로 전달한다.
- 360px에서 가로 스크롤 없이 핵심 입력과 탭을 사용할 수 있어야 한다.

## 9. TDD 및 검증 순서

각 기능은 실패하는 테스트를 먼저 추가하고 최소 구현 후 리팩터링한다.

1. 카테고리 단일 필터와 기존 월·유형·검색 조합
2. 거래 수정의 정상·오류·존재하지 않는 ID 처리
3. 날짜별 지출·수입·건수 집계와 예산 기간 경계
4. Supabase 거래 행 단위 매핑과 추가·수정·삭제
5. 탭, 월 이동, 수정 모달, 캘린더 UI 연결
6. 저장 실패와 포커스 복원 회귀 테스트

자동 검증 명령은 다음을 포함한다.

```bash
node --check js/storage.js
node --check js/transactions.js
node --check js/ui.js
node --check js/app.js
node --check js/cloud.js
node tests/run-tests.cjs
git diff --check
```

브라우저 검증은 로그인 상태에서 예산 저장과 원상 복원, 쉼표 금액 입력, 거래 추가·수정·삭제, 지난달 이동, 필터 조합, 캘린더 상세, 콘솔 오류, 키보드 흐름, 모바일 360px를 확인한다.

## 10. 문서화

기능과 실제 동작이 일치하도록 다음 문서를 필요한 범위에서 갱신한다.

- `README.md`
- `docs/TEST_PLAN.md`
- `docs/IMPROVEMENT_LOG.md`
- Supabase 저장 동작을 설명하는 기존 문서

미리보기 URL, 운영 데이터 사용 경고, 운영 승격 커밋을 개선 로그에 기록한다.

## 11. 완료 조건

- 다섯 가지 요청 기능이 모두 구현됐다.
- 과거 월에서도 수정·삭제가 동작한다.
- 일반 거래 변경이 Supabase 행 단위로 저장된다.
- 다른 브라우저의 관련 없는 거래 전체를 덮어쓰지 않는다.
- 자동 테스트, syntax check, diff check가 통과한다.
- 미리보기 공개 URL에서 데스크톱·모바일·키보드 핵심 흐름을 검증했다.
- 미리보기에서 QA로 만든 운영 데이터가 모두 정리됐다.
- 사용자가 미리보기를 승인하기 전 운영 `master`는 변경되지 않는다.
- 사용자 승인 후 동일 검증 커밋이 운영에 배포되고 운영 URL에서도 재검증됐다.
