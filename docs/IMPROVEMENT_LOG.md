# 개선 진단 및 반복 로그

## 2026-10-22 · 홈 요약을 브리핑 카드 레이아웃으로 개편 (브랜치 feature/home-card-layout)

- 홈 '이번 달 요약'을 아침 브리핑 카드와 같은 구성으로 바꿨다. 맨 위에 잔액(예산 남은 금액, 강조)·사용(지출 합계)·총예산(월 예산) hero 3박스를 두고, 그 아래에 기존 예산 사용률 미터를 유지했다. 수입 합계와 '수입 − 지출' 카드는 지우지 않고 hero 아래 보조 카드 줄로 옮겼다.
- '카테고리별 지출'은 카테고리명·막대(가장 많이 쓴 카테고리 대비 상대 너비)·금액 행으로 바꿨다. 색상은 앱 기존 CSS 변수와 카드 스타일을 그대로 쓰고 브리핑 이미지의 색은 복제하지 않았다.
- '장소별 지출' 섹션을 새로 넣었다. transactions에 merchantBreakdownFor를 추가했다: 지출만 대상, 장소 키는 메모 정규화(쿠팡이츠 포함 시 '쿠팡이츠', 쿠팡 포함 시 '쿠팡', 빈 메모는 '메모 없음'), 상위 5곳 + 나머지는 '기타' 하나로 합산. summarize는 coupangTotal(쿠팡+쿠팡이츠)과 coupangRate(총지출 대비 %, 소수 1자리)도 제공해 섹션 아래에 강조 줄로 표시한다.
- '어제 사용 내역' 섹션을 새로 넣었다. summarize의 yesterdayExpenses(today 기준 어제 날짜의 지출 전체, 최신순)를 항목명 — 금액 · 카테고리로 보여주고, 없으면 '어제 사용 내역이 없어요'를 표시한다.
- 검증: TDD로 merchant 정규화·상위 5+기타 합산, summarize의 신규 필드, 홈 카드 마크업, renderSummary 렌더를 검증하는 테스트 4개를 먼저 실패시킨 뒤 구현해 전체 95개 회귀와 cashflow·fixed-cost·phone·tasker 별도 스위트가 모두 통과했다. 헤드리스 크롬 렌더에서 새 섹션과 오류 없음을 확인했다.


## 2026-10-22 · 항목별 예산 관리를 없애고 월 총예산만 관리 (브랜치 feature/total-budget-only)

- 예산은 월 총예산(200만원) 하나로만 관리한다. 카테고리는 예산을 배정하지 않고 카테고리별 사용액만 본다. 사용자 결정에 따른 구조 단순화다.
- 홈의 '카테고리별 남은 예산' 블록과 설정의 '항목별 잔액' 섹션(항목별 예산 입력 폼·예산 옮겨 쓰기 폼)을 제거했다. '카테고리별 지출' 블록은 그대로 둔다. 안내 문구는 "카테고리별 사용액" 기준으로 바꿨다.
- transactions에서 setCategoryBudgets·transferCategoryBudget·categoryBudgetAvailability와 summarize의 categoryBudgetStatus를 제거했다. summarize는 categoryBreakdown(카테고리별 사용액)만 제공한다. 분류 탭의 카테고리 라벨에도 예산 잔액을 붙이지 않는다.
- 저장 데이터의 categoryBudgets 정규화와 클라우드 동기화는 기존 데이터 호환을 위해 그대로 뒀다. 남아 있는 과거 카테고리 예산 값은 화면에 표시되지 않을 뿐 삭제되지 않는다.
- 검증: TDD로 관련 테스트를 새 스펙으로 교체(제거된 API 부재, summarize의 categoryBreakdown 제공·categoryBudgetStatus 부재)한 뒤 전체 91개 회귀와 폰 관련 테스트 25개가 통과했다.

## 2026-10-21 · 쿠팡 웹 주문 상세를 수신함에 연결 (브랜치 feature/coupang-order-import)

- 쿠팡 웹(www.coupang.com) 주문 상세를 새 수신 종류 coupang_order로 받는다. 주문번호를 이벤트 ID로, 주문 결제일시를 수신 시각으로 써서 같은 주문을 다시 수집해도 중복 카드가 생기지 않는다. docs/supabase-coupang-order.sql을 기존 폰 SQL 다음에 한 번 실행해야 하며, 아직 운영 Supabase에는 실행하지 않았다.
- 기기 토큰을 기기별로 분리했다(A안). phone_devices 기본키가 (사용자, 환경, 토큰 해시)가 되어 연결 설정을 새로 만들어도 다른 기기의 토큰이 무효가 되지 않는다. 해시를 지정하면 그 기기만, 지정하지 않으면 환경 전체를 해제한다. 웹 연결 화면의 "이전 연결키는 사용할 수 없어요" 문구와 해제 범위 표시는 후속으로 맞출 예정이다.
- 주문 연결(link_phone_order)이 coupang_order도 받는다. 취소·환불 주문은 서버에서도 연결을 거부한다. 검토 초안은 쿠팡 주문을 카드 결제 금액 우선·생활비 기본·기존 결제 연결 제안으로 채우고, 취소·환불이면 제외를 제안한다. 금액 라벨은 '카드 결제 금액'처럼 띄어 쓴 표기도 읽는다.
- 수집기 프로토타입은 저장소 밖 coupang-ledger/collector에 있다. 주문 JSON을 수신 페이로드로 바꾸고 공용 검증으로 확인한 뒤 기본은 출력만 하고, 환경변수가 있을 때만 전송한다. 종결 상태(배송완료·구매확정·취소·환불) 주문만 대상으로 한다.
- 검증: 기존 97개 회귀, 폰·Tasker 테스트 48개, 격리 PostgreSQL 테스트 4종(기존 3종 + 쿠팡 신규)이 통과했다. 실제 쿠팡 주문 수집과 운영 서버 반영은 아직 하지 않았다.

## 2026-10-21 · 현금흐름의 고정비 점검

- 고정 납부 항목에 납부일·결제수단·점검 상태·목표 월 금액·메모를 추가했다. 고정비만 보기는 수입 등 다른 항목을 숨기기만 하며 저장과 계산에 유지한다.

- 모델 검증, 기존 현금흐름 테스트, 기존 97개 회귀 테스트 및 Chromium의 저장 성공/실패·상태별 예상액·고정비 필터·월 복사·360/1280px·로그아웃 스모크를 통과했다. 브라우저 저장 검증은 모의 클라우드로 수행했다.

## 2026-10-17 · 분류할 것 전용 탭

- 미처리 카드 결제 후보를 분류 탭에 모으고 남은 건수 배지를 표시한다. 로그인·탭 열기·화면 복귀 시 자동 조회하고 탭이 보일 때 30초마다 확인한다. 최근 미처리 알림 최대 100건 기준이다.
- 한 개의 명확한 금액, 결제일 또는 수신일, 설명을 미리 채운다. 수신일을 썼으면 명시한다. 분류 버튼 한 번으로 기존 수신함 기록 RPC를 호출하며 같은 날짜·금액이 있거나 정보가 부족하면 상세 확인으로 보낸다.
- 지출 후보가 아닌 이동·시험·주문 자료는 접힌 보관 영역으로 분리한다. 수정 중 자동 갱신은 멈추고 실패 시 입력을 유지한다. 기록은 기존 내역 탭에서 수정할 수 있다.
- Tasker 설정·프로젝트 재설치는 필요 없다. 쿠팡/쿠팡이츠 앱 자동 조작이나 잠금 해제 자동화는 이 변경에 포함되지 않는다.

- 00:29:32 KST 새 연결 시험의 운영 서버 수신을 확인했다. 복원 파일의 실제 Android 가져오기와 새 결제 알림 수집은 미확인이다.

## 2026-10-17 · 재발급 키와 미전송 알림의 연결 복구

- 사용자 폰은 미전송 알림 때문에 연결 변경을 막았지만 서버는 키 재발급 때 이미 이전 키를 무효화했다. 이전 연결로 먼저 보내라는 안내로는 복구할 수 없는 경로를 테스트로 재현했다.
- 같은 서버의 기존 대기열에 한해 사용자가 같은 계정·가계부임을 확인하면 원문·ID를 유지해 재전송한다. 이전 대기열은 폰에 한 개의 복구 백업으로 남긴다. 취소·다른 서버·혼합 연결·손상 데이터·진행 중 전송·도중 상태 변경에는 쓰지 않는다.
- 수정 파일에 BB 연결 복구를 추가했다. 기존 BB 시작·알림 프로필은 수정 파일에서 교체하지 않는다. 전체 설치의 BB 시작에도 같은 복구 로직을 반영했다.
- Tasker/알림 27개, 기존 가계부 97개, Chrome 설치·진단·복구 페이지 800/360/320px 검증 통과. 격리 PostgreSQL에서 재발급 키로 원래 ID를 재전송하면 중복 수신되지 않고 이전 키는 차단됨을 확인했다. 실제 폰에서 복구 실행·남은 알림 전송은 별도 확인이 필요하다.

## 2026-10-16 · Tasker 실기기 진단 후 변수 전달 수정

- 사용자 폰에서 기본 오류 화면이 열렸고, URL 찾아보기의 패키지/앱이름에 `%` 경고가 표시됐다. 브라우저 열기 자체는 확인했지만 그 화면만으로 JavaScriptlet 예외나 서버 연결 실패를 확정할 수 없었다.
- Auto Exit 때 주입된 JS 지역 변수가 다시 반영되는 실행 경계를 모델링하자 초기 진단 URL 유지와 재전송의 이전 값 유지가 재현됐다. 기존 setLocal 모형은 이 반영 단계를 누락했다. 상태 URL·송신 준비·응답 확인 값을 최상위 JS 바인딩으로 내보내도록 바꿨다.
- 기본 브라우저 액션은 잘못된 빈 App 객체를 없애고 URL만 지정한다. 기존 연결키와 프로필을 유지하며 BB 연결 확인·BB 보내기만 교체할 수정 묶음을 추가했다.
- 수정 후 알림·Tasker 테스트 24개와 기존 가계부 97개, XML 참조·문법·diff 검사 및 Chrome의 수정/진단/설치 페이지 다운로드·320/360/800px·오류 분기를 통과했다. 서버 읽기 전용 확인에서는 연결 시험 1건만 수신된 상태다.
- 이 항목은 재현과 수정 내용이다. 실제 Android에서 수정 작업 교체 후 진단 값 전달·케이뱅크 수신이 해결됐는지는 사용자 폰 결과로 확인해야 한다. 새 테스트 모델을 실기기 증거로 주장하지 않는다.

## 2026-10-16 · Tasker 상태창 진단

- `BB 상태` 실행이 끝나도 팝업이 보이지 않는 사용자 보고에 대응해 상태 표시를 브라우저 화면으로 바꿨다. 팝업이 안 뜬 원인이나 케이뱅크 알림 누락 원인을 확정한 것은 아니다.
- 기존 사용자를 위한 별도 `가계부 연결 진단` 프로젝트와 `BB 연결 확인` 작업을 추가했다. 연결키·대기열·프로필을 수정하지 않고 연결 시험 기록·미전송 개수·마지막 처리 상태만 읽는다. 비밀키와 알림 본문은 화면 주소에 넣지 않는다.
- JavaScriptlet 실패 시에도 기본 오류 URL을 여는 네이티브 액션을 둔다. 코드 실패·설정 손상·전송 대기·수집 오류를 구분해 다음 확인을 안내한다.
- TDD에서 기존 팝업 의존, 별도 진단 빌더 미구현, 손상된 설정의 정상 판정 실패를 확인한 뒤 수정했다. Tasker·알림 테스트 21개와 기존 가계부 97개, 표준 XML 파싱 및 Chrome의 320/360/800px 화면·다운로드·오류 분기·키보드 검증을 통과했다.
- 현재 서버에는 실제 폰의 연결 시험 1건이 있고 케이뱅크 실알림은 아직 없다. 새 진단 작업의 Android 가져오기·브라우저 열기와 실제 알림 수집은 폰에서 확인해야 한다. 이번 변경은 DB와 실제 거래를 수정하지 않는다.

## 2026-10-16 · Tasker 일괄 가져오기

- 작업과 프로필을 직접 만들던 과정을 설치 버튼 한 번으로 가져오는 프로젝트로 묶었다. 스크립트는 XML 안에 포함하고 개인 연결키는 포함하지 않는다.
- BB 시작에서 연결 설정을 붙여 넣으면 지출이 아닌 시험 이벤트를 전송한다. 동일한 시험 ID의 서버 성공 응답 전에는 새 알림 수집을 시작하지 않는다.
- 이전 연결의 미전송 알림은 새 연결로 보내지 않으며, 전송 실패 시 대기열을 보존한다. 쿠팡이츠 화면 수집은 앱 패키지와 사용자 확인을 모두 요구한다.

- 미리보기 복사본에서 불변 접두사 `<marker> = QA-V1-<timestamp>`와 생성 직후 기록한 QA ID를 사용한 추가·수정·필터·캘린더·삭제, 모든 월과 `preview_transactions`의 0건 확인, 미리보기 예산 원복 검증이 남아 있다.
- 공개 `/beginner-budget-preview/v1/` 배포, 소스 SHA 매니페스트 확인, 공개 URL 재검증이 남아 있다.
- `docs/supabase-setup.sql` 운영 적용과 운영 승격은 사용자가 미리보기 URL을 선택한 뒤까지 대기한다.

따라서 당시 결과는 **코드·자동 테스트와 이전 로컬 비로그인 UI 스모크 근거 확보**였으며, 미리보기 인증 저장 흐름, DB 격리 SQL 런타임, 공개 미리보기 검증 완료를 뜻하지 않았다.

### 최초 seed와 최종 운영 승격 하드 게이트

최초 미리보기 seed는 writer의 다중 요청 중간 상태를 복사하지 않도록 **짧은 운영 쓰기 중단 창**에서만 수행한다. 운영·미리보기·로컬 로그인 탭을 모두 닫고 API를 포함한 모든 쓰기를 중단한 뒤 `READ COMMITTED` seed와 canonical settings·canonical transactions 전체 행/값 양방향 비교를 끝낸다. 그 뒤에만 세 환경의 쓰기를 재개하며, marker 삭제를 통한 명시적 reseed는 별도 검토 절차 없이 실행하지 않는다.

사용자가 특정 URL을 승인한 뒤에는 이 짧은 seed 창과 별도로, 운영 SQL 적용 직전에 단일 배타적 쓰기 창을 연다. 모든 기기의 구버전 운영 탭을 닫고 창 안에서 기준 백업, 사용자별 행 수, 결정적 ID 매핑, 매핑 간·기존 ID 충돌 감사를 authoritative 자료로 확정한다. 운영 SQL과 사용자가 선택한 정확한 안전 소스 SHA를 승격하고 운영 URL의 새 다운로드·인증 스모크·QA 정리를 끝낼 때까지 창을 유지한다.

## 2026-10-16 — Tasker 휴대폰 알림 수신 준비

- 케이뱅크·쿠팡이츠 알림 및 수동으로 연 쿠팡이츠 화면을 위한 수신함, 연결키, 확인 후 지출 기록 화면 추가.
- 연결키는 서버에 해시만 저장하고 사용자/환경을 서버에서 결정. 기존 거래 전체 교체 없이 한 건만 원자적으로 insert.
- Tasker 대기열, 같은 ID 재전송, 성공 확인 후 제거, 연결 변경 시 이전 대기열 전송 차단 추가.
- 쿠팡 주문 매칭 순수 함수와 모호한 후보 보류 규칙 추가. 실제 수집기나 자동 DB 보강에는 아직 미연결.
- 실알림을 받기 전이므로 알림 문구 기반 자동 지출 확정은 구현하지 않음. 공개 자료를 사용자 실데이터로 간주하지 않음.
- PostgreSQL 격리 런타임·시험 브라우저 검증과 실제 Supabase 적용·폰 검증을 구분. 배포/실기기 검증은 미완료.
